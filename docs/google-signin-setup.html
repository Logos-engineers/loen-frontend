Google 로그인 전체 흐름

왜 google-services.json이 필요한지, 런타임에서 어떻게 동작하는지

1 — 왜 google-services.json이 필요한가

Android 앱에서 Google Sign-In을 사용하려면 Google 서버가 "이 앱이 정말 등록된 앱인지" 확인해야 합니다. google-services.json은 그 확인에 필요한 정보(프로젝트 번호, OAuth 클라이언트 ID, SHA-1 지문 등)를 담은 설정 파일입니다.

✕ 파일 없을 때

Android 앱이 Google 서버에 "나 어떤 프로젝트 앱이야"를 알려줄 방법이 없음

→ Google이 요청을 거부 = DEVELOPER_ERROR

✓ 파일 있을 때

앱 빌드 시 파일이 네이티브 코드에 포함됨

→ Google이 클라이언트 인식 → 로그인 정상 동작

ℹ️
Firebase를 실제로 쓸 필요는 없습니다. Firebase Console은 google-services.json을 발급해주는 창구로만 활용합니다. 백엔드는 Railway 그대로 사용합니다.
2 — google-services.json 발급 단계
  1. Firebase Console 접속
    console.firebase.google.com → 프로젝트 추가 → 기존 Google Cloud 프로젝트 선택 (loen 프로젝트가 목록에 보임)
  2. Android 앱 등록
    프로젝트 생성 후 Android 아이콘 클릭
    · 패키지 이름: com.loen.app
    · SHA-1: 59:C9:66:67:29:E1:78:C8:3B:41:D8:16:5B:28:22:66:23:B4:9C:9C
  3. google-services.json 다운로드
    등록 완료 후 파일 다운로드 버튼 클릭
  4. 프로젝트 루트에 파일 배치
    loen-frontend/google-services.json 위치에 저장
  5. 재빌드
    npx expo run:android — 빌드 시 파일이 네이티브 코드에 포함됨
⚠️
google-services.json에는 프로젝트 정보가 담겨 있습니다. .gitignore에 추가하거나 팀 내부 채널로만 공유하세요.
3 — 런타임 로그인 흐름

설정이 완료된 후 "Google로 시작하기" 버튼을 누르면 아래 순서로 동작합니다.

📱 앱
🔵 Google 서버
🟢 백엔드 (Railway)
① 로그인 버튼 클릭
▶
GoogleSignin.signIn()
② 네이티브 다이얼로그
◀
Google 계정 선택 팝업 표시
③ 계정 선택 완료
▶
idToken 반환
④ 백엔드 전송
▶
POST /auth/login { idToken }
⑤ JWT 발급
◀
accessToken + refreshToken 반환
⑥ 로그인 완료
토큰 SecureStore 저장 → 홈 화면 이동

브라우저를 열지 않고 네이티브 Google 다이얼로그로 처리하므로 redirect URI 문제가 없습니다.

4 — 기존 방식 vs 현재 방식
항목expo-auth-session (구)@react-native-google-signin (현)
동작 방식 브라우저 열어서 OAuth 처리 네이티브 Google 다이얼로그
redirect URI 필요 ✓ (Google 정책 충돌 발생) ✗ (필요 없음)
Expo Go 지원 ✓ (auth.expo.io 프록시 — 폐기됨) ✗ (Development Build 필요)
Development Build 구조적 문제로 동작 불가 ✓ 정상 동작
필요 파일 .env만 있으면 됨 google-services.json 추가 필요
백엔드 연동 idToken → POST /auth/login idToken → POST /auth/login (동일)
