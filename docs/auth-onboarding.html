2 Expo Go vs Development Build — 반드시 읽어야 함

Expo로 개발할 때 앱을 실행하는 방법이 두 가지입니다. 어떤 방식을 쓰느냐에 따라 Google 로그인 가능 여부가 달라집니다.

Expo Go (기존 방식)

앱스토어에서 받은 범용 앱으로 QR 스캔해서 실행

URL 스킴이 exp://로 고정

Google OAuth가 exp://를 거부 → 로그인 불가

UI 작업에는 충분함

Development Build (새 방식)

우리 앱을 직접 빌드해서 설치

URL 스킴이 loenproject://로 등록됨

Google OAuth 정상 동작 → 로그인 가능

핫리로드도 동일하게 됨

왜 Expo Go에서 Google 로그인이 안 되나?

Google OAuth는 로그인 후 앱으로 돌아올 때 redirect URI를 사용합니다. Expo Go에서는 이 URI가 exp://192.168.x.x:8081로 생성되는데, Google의 보안 정책상 exp:// 스킴은 허용하지 않습니다.

Google 로그인 시도
→
redirect to exp://...
→
Google이 거부
Google 로그인 시도
→
redirect to loenproject://
→
Google이 허용

그래서 뭘 써야 하나?

작업 종류추천 방식이유
UI 화면 레이아웃, 스타일 작업 Expo Go 로그인 불필요, 빠르고 간편
인증 Google 로그인 테스트 Development Build Expo Go에서 구조적으로 불가능
인증 로그인 후 화면 테스트 Expo Go + DEV 로그인 DEV 버튼으로 토큰 발급 후 테스트 가능

3 환경변수 설정 (.env)

⚠️
.env는 .gitignore에 포함되어 레포에 없습니다. 아래 내용을 직접 만들어야 합니다.

프로젝트 루트 loen-frontend/에 .env 파일을 만들고 아래 내용을 붙여넣으세요.

# loen-frontend/.env

# Google OAuth Client IDs
EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID=114111779962-4bsm5eksojocqnmbp5p3sb9dt0tbhds6.apps.googleusercontent.com
EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID=114111779962-hcpu1cde4n5c0or7rbkv4tsejdd8sslh.apps.googleusercontent.com
EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID=114111779962-rb60sph3k2mj4edmn2680m9ebaqttno9.apps.googleusercontent.com

# 공용 개발 서버 사용 시 추가 (없으면 localhost로 연결)
# EXPO_PUBLIC_API_URL=http://100.118.241.66:8080/api/v1
⚠️
EXPO_PUBLIC_* 변수는 Metro 기동 시점에 읽힙니다. .env 파일 생성·수정 후에는 Metro를 반드시 재시작해야 적용됩니다 (npx expo start 재실행).

4 UI 작업 셋업 — Expo Go

UI 작업만 할 때는 기존과 동일하게 Expo Go를 사용하면 됩니다.

  1. 레포 clone 후 npm install
  2. .env 파일 생성 (3번 섹션 참고)
  3. npx expo start 실행
  4. Expo Go 앱으로 QR 스캔
  5. 로그인이 필요한 화면 진입 시 → DEV 로그인 버튼 사용
✅
DEV 로그인 버튼은 백엔드에서 테스트용 토큰을 즉시 발급해줍니다. Google 로그인 없이도 로그인 이후 화면을 자유롭게 테스트할 수 있습니다. __DEV__ 모드에서만 표시되며 프로덕션에는 없습니다.
⚠️
Expo Go에서 "Google로 시작하기" 버튼을 누르면 오류가 납니다. 이것은 코드 버그가 아니라 Expo Go의 구조적 한계입니다.

5 Google 로그인 테스트 — Development Build

Google 로그인 자체를 테스트하려면 Development Build가 필요합니다. 한 번 빌드해두면 이후에는 Expo Go와 동일하게 핫리로드로 개발할 수 있습니다.

로컬에서 빌드 (Mac + Xcode / Android Studio 필요)

# 1. expo-dev-client 설치 (최초 1회)
npx expo install expo-dev-client

# 2. iOS 빌드 & 시뮬레이터에 설치 (Mac + Xcode 필요)
npx expo run:ios

# 3. Android 빌드 & 에뮬레이터에 설치 (Android Studio 필요)
npx expo run:android

빌드 완료 후에는 시뮬레이터에 앱이 설치됩니다. 이후 JS 코드 수정은 npx expo start로 핫리로드 됩니다.

Mac이 없을 때 — EAS Cloud 빌드

# EAS CLI 설치 (최초 1회)
npm install -g eas-cli
eas login

# Android 개발 빌드 (클라우드에서 빌드 → 설치 링크 제공)
npx eas build --platform android --profile development
ℹ️
EAS 빌드는 Expo 클라우드 서버에서 빌드하므로 로컬에 Android Studio가 없어도 됩니다. 빌드 완료 후 QR코드로 .apk를 설치할 수 있습니다.

네이티브 재빌드가 필요한 경우

한 번 빌드한 뒤에는 아래 상황에서만 다시 빌드하면 됩니다:

상황재빌드 필요?
화면 컴포넌트 수정, 스타일 변경불필요 (핫리로드)
새 npm 패키지 추가 (JS only)불필요
app.json 플러그인 변경필요
새 네이티브 라이브러리 추가 (expo-camera 등)필요

Silent Refresh

API 호출 시 401 응답이 오면 apiClient.ts가 자동으로 토큰을 갱신하고 원본 요청을 재시도합니다. 컴포넌트에서는 별도 처리 없이 apiClient()만 호출하면 됩니다.

API 호출
→
401 응답
→
POST /auth/refresh
→
토큰 갱신
→
원본 요청 재시도
⚠️
Refresh도 실패하면 자동으로 로그아웃 처리됩니다. 컴포넌트에서 "세션이 만료되었습니다" 에러가 잡히면 로그인 화면으로 안내하면 됩니다.

7 인증 관련 주요 파일

파일역할
store/auth-store.ts Zustand 인증 상태 관리. 토큰 in-memory 보관, SecureStore로 영속화. initialize() · setTokens() · clearTokens()
utils/apiClient.ts 모든 API 호출 통합 처리. Authorization 헤더 자동 주입, 401 응답 시 Silent Refresh 후 1회 재시도.
app/login.tsx 로그인 화면. Google OAuth (Authorization Code + PKCE) + DEV 로그인 버튼.
app/profile-setup.tsx 신규 유저 프로필 설정 화면. 현재 placeholder, 실제 구현 예정.
app/_layout.tsx 인증 상태 기반 라우팅 가드.

8 빠른 셋업 체크리스트

UI 작업만 할 때

  1. 레포 clone 후 npm install
  2. loen-frontend/.env 파일 생성 (3번 섹션 내용 붙여넣기)
  3. 공용 서버 쓸 경우 EXPO_PUBLIC_API_URL=http://100.118.241.66:8080/api/v1 추가
  4. npx expo start 실행
  5. Expo Go로 QR 스캔 → DEV 로그인 버튼으로 로그인

Google 로그인 테스트가 필요할 때

  1. 위 1~3번 동일하게 진행
  2. npx expo install expo-dev-client
  3. npx expo run:ios 또는 npx expo run:android (최초 1회 빌드, 5~10분 소요)
  4. 이후엔 npx expo start로 개발 서버만 실행하면 핫리로드 됨
